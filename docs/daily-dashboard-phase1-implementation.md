# داشبورد روزانه — Phase 1 Implementation

## هدف
اجرای فاز ۱ معماری مرکز عملیات روزانه بدون تغییر دادن مدل دامنه اصلی و بدون حذف کنترل فعلی داشبورد.

## موارد پیاده‌سازی‌شده

### Action Center
`daily-command-center.api.ts` شاخص‌های عملیاتی لازم را فراهم می‌کند و ماژول `daily-command-center.js` آن‌ها را به بخش «نیازمند اقدام» تبدیل می‌کند:
- حضور هنرجوی ثبت‌نشده
- حضور مدرس ثبت‌نشده
- جلسه بدون اتاق
- تداخل مدرس
- تداخل اتاق
- ترم دارای معوقه
- موارد نزدیک تمدید

### KPI مالی
- پرداخت‌های ثبت‌شده در تاریخ انتخاب‌شده
- تعداد تراکنش‌های روز
- تعداد ترم‌های دارای مانده
- تعداد ترم‌های دارای معوقه

### KPI تمدید
تعداد ترم‌های فعال که ماهانه هستند یا طبق قاعده فعلی حداکثر یک جلسه مصرف‌نشده دارند.

### وضعیت استاد
برای هر مدرس:
- تعداد جلسات
- بازه زمانی اولین تا آخرین جلسه
- تعداد حضور ثبت‌نشده
- تعداد غیبت
- وضعیت تکمیل حضور

### Conflict
منطق Phase 1 دو نوع تداخل را مستقل می‌سنجد:
- تداخل زمانی مدرس
- تداخل زمانی اتاق

این عمداً جایگزین مفهوم قبلی «تداخل هم‌زمان مدرس و اتاق» است.

### Quick Search
جستجوی سریع Backend برای:
- هنرجو
- مدرس
- کلاس

نتایج محدود به ۲۰ مورد هستند و جستجو با LIKE و escape کردن wildcardها انجام می‌شود.

## فایل‌ها
- `src/pages/api/admin/daily-command-center.api.ts`
- `src/scripts/admin/daily/daily-command-center.js`
- `src/styles/admin/daily-command-center.css`

## وضعیت اتصال به صفحه اصلی
ماژول UI آماده است، اما در این مرحله اتصال مستقیم آن به `src/pages/admin/daily.astro` به دلیل خطای optimistic-concurrency در GitHub Contents API روی فایل موجود، هنوز commit نشده است. فایل اصلی حذف یا بازنویسی نشده تا ریسک خراب‌شدن داشبورد فعلی ایجاد نشود.

## تصمیم معماری
ماژول Phase 1 از API مرکز عملیات داده می‌گیرد و برای جلوگیری از دستکاری مستقیم DOM کنترلر اصلی طراحی شده است. در مرحله بعد، پس از امکان patch امن فایل اصلی، این presentation layer باید در نهایت داخل همان Single Controller / Single State ادغام شود تا دو state مستقل نداشته باشیم.

## موارد بعدی قبل از merge
1. اتصال `daily-command-center.js` به `daily.astro` یا ادغام آن در `daily-dashboard.js`.
2. افزودن NOW line به Timeline کنترلر اصلی.
3. اتصال Action Center به Session/Student target واقعی، نه فقط نمایش شمارنده.
4. افزودن navigation از نتیجه Search به رکورد مرتبط.
5. اجرای build/typecheck و تست D1 روی داده واقعی.
6. اصلاح timezone به‌عنوان بخشی از قرارداد روز مدرسه.
